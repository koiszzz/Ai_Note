## 摘要

- 无论你刚开始还是完全非技术岗位，你可能已拥有构建自己工具所需的技能；律师、项目经理与商务专业人士（非工程师）团队的大量工作重复：反复评审同类合同、回答相同法律问题，先前指导常被回收。
- GitHub Copilot CLI 让团队用自然语言提出需求、接入仓库并快速看到真实变化："我永远写不了代码"变成"我刚做了个东西"，习惯自行蔓延到每个人都开始构建。
- 案例一（Ngandu Kasuku，首席产品顾问）：用 Copilot CLI 创建合同起草工具 terms-ai——脚手架项目、在仓库中存储关键文档、版本化指导指令与起草资源；主要功能是内部起草风格指南（以简明语言运动为原则）；还构建已完成协议库，现有伙伴发来附录或新协议时可参考先前工作；评审与起草时间约减半，条款跨协议更一致。
- 案例二（Jesse Geraci，网络安全顾问）：从窄问题开始——快速准确分析源码以评估 DMCA 通知；核心"编程"是纯语言文件（工作流指令集、政策参考材料与报告模板），把结构化法律判断构建进工作流本身；扩展了不同分析模式（客户与律师：客户更快输出与升级建议，律师更深入评审与双方论证）与外部数据源；后来演变为完整桌面应用，核心指令用纯语言轻松编辑定制。
- 关键教训：不需要等待完美软件厂商或成为全职开发者就能构建严肃 AI 工具；能清晰定义方法论、标准与输出格式，GitHub Copilot 就能轻松把知识操作化；法律 Copilot 不是法律判断的替代品，而是让人工评审保持核心、同时让法律分析更一致、更透明、更可扩展的结构化决策支持系统。

## 正文

以下是文章全文翻译。

无论你刚刚开始还是完全不处于技术岗位，你可能已经拥有构建自己工具所需的技能。如果你曾想过"我不够技术，构建不了那个"，这篇文章为你而写。让我介绍团队。我们是律师、项目经理与商务专业人士——不是工程师。我们工作很大一部分常是重复的，比如反复评审同类型合同或回答相同法律问题，我们先前的指导经常被回收。这些是 AI 可以帮忙解决的问题，但我们缺乏构建正确工具的信心。这时 GitHub Copilot CLI 出现了。我们用自然语言提出想要的东西，接入仓库，很快看到真实变化。"我永远写不了代码"变成"我刚刚做了个东西"，这个习惯自行蔓延，直到我们每个人都在构建东西。下面是两个真实故事，另有两个故事见视频。

**我为什么构建内部起草风格指南。** 以下是 Ngandu Kasuku（首席产品顾问）的第一人称叙述。我是产品律师，但商业工作仍占我执业相当大比例。约三月或四月，我埋头于涉及数据、基础设施与产品集成的伙伴交易。没有两笔交易看起来相似，每个新事项都像从头开始。我开始用 Copilot CLI 管理这股浪潮，它有帮助但也有问题。看到别人用 Copilot 构建的东西后，我意识到我格局不够大。与其一次一个任务地用 AI，我可以围绕自己的工作方式构建东西。于是我用 Copilot CLI 创建了合同起草工具，取名 terms-ai，我承认这不是最有创意的名字。我先脚手架项目并把关键文档存入仓库，这给我一个地方组织与版本化指导 AI 的指令、起草资源与工作流。该结构使结果更一致，减少了我用提示库时拖慢速度的复制粘贴。工具主要功能之一是内部起草风格指南。自商业律师时代起我就偏爱简明语言，从不理解合同为何需要"heretofore""therewith"这类词。当我发现整个法律起草运动都持此观点时，我用其原则作为风格指南基础。我还构建了已完成的协议库。现在当现有伙伴发来附录或新协议时，工具可参考先前工作。这些协议留在经批准的、访问受控的内部环境中。工具与一般工作流是开源的；协议与其他敏感信息不在开源仓库中。自用 terms-ai 以来，我把评审与起草时间大约减半。条款跨协议更一致，草稿反映我偏爱的简明风格。工具还有很长路要走。但最大的教训不是 AI 能帮我更快起草，而是我可以用 AI 围绕自己的判断、经验与工作方式构建工具。

**我如何在不写传统代码的情况下构建法律工作流。** 以下是 Jesse Geraci（网络安全顾问）的第一人称叙述。我从一个窄问题开始。我们需要快速准确地分析源代码以评估 DMCA（数字千年版权法）通知。最初项目是一组用于重复任务的 GitHub Copilot 指令：DMCA 分流、代码比较、许可检查与规避审查。我们想把每个人独立做的凌乱、一次性的提示工作变成可重复、法律团队能信任其收集正确事实并一致分析数据的东西。令我惊讶的是没有工程支持我能走多远。核心"编程"是纯语言文件，由工作流指令集、政策参考材料与报告模板组成。我没有写源代码，而是用作为律师的语言创作技能把结构化法律判断构建进工作流本身。它从此成长。我们为客户与律师添加不同分析模式（客户更快输出与升级建议；律师更深入评审与双方论证），并集成外部数据源。把工作流交给团队时，他们立即开始使用并让 Copilot 做更多。该基础此后演变为一个完整桌面应用，在干净界面中运行预定义法律工作流。构建桌面应用需要写一些代码（实际上很多），但用于定制工作流的核心指令在应用内用纯语言轻松编辑与定制。我们创建的应用现已远超 DMCA 通知的代码分析。它包含许多内部工作流的指令：合同评审、NDA 分流、风险评估、合规检查与响应起草。底层可经可复用技能与智能体（受理、剧本对齐、风险评分、证据验证、升级路由、报告组装）路由工作，但重要的不是技术复杂度——而是法律团队仍能在可读 Markdown 中控制行为。对我而言，关键教训是我无需等待完美软件厂商——或成为全职开发者——就能构建严肃 AI 工具。如果你能清晰定义方法论、标准与输出格式，GitHub Copilot 就让你轻松把知识操作化。我的法律 Copilot 不是法律判断的替代品，也不应被这样对待。它是结构化决策支持系统，让人工评审保持核心，同时让法律分析更一致、更透明、更可扩展。

**带走。** 如果一队律师与项目经理能快速构建脱离艰难日子，你也可以。许多工作——即使不围绕传统软件开发——都有可自动化的重复任务。挑一件拖慢你的事，打开 Copilot CLI，请它帮你构建修复。
