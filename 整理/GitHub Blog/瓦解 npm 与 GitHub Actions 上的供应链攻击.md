# 瓦解 npm 与 GitHub Actions 上的供应链攻击

## 摘要

- 过去一年出现一种供应链攻击模式：瞄准包仓库与 CI/CD 系统的弱点，把恶意软件快速传播到数百个开源项目；此类恶意软件寻求窃取凭据以广泛传播并供后续利用。
- 供应链攻击把多个弱点串成链条，没有单一安全能力能阻止它们；整体方法优先打破攻击链中最有影响的环节。
- 初始入侵：攻击从攻破单个项目开始（直接攻破维护者账户或瞄准项目 Actions 工作流）。对应改进包括：npm 对高影响账户的预防性账户保护（改邮箱或使用 2FA 恢复码后 72 小时只读，给维护者时间恢复账户）；更安全的 pull_request_target 默认值（actions/checkout 默认行为改变，阻止在常见被利用触发器中检出分叉的不受信任代码，除非显式退出）；新的触发控制（企业/组织/仓库级策略规定谁可触发工作流与允许哪些触发类型）；不受信任触发器的只读 Actions 缓存（限制低信任工作流修改与其他工作流共享的缓存）。
- 凭据窃取：攻击者窃取凭据以扩大访问。对应改进包括：npm 可信发布现在支持 CircleCI（消除长期凭据）；Actions 网络防火墙（技术预览，记录所有出站网络流量以检测异常行为）。
- 传播攻击：用窃取凭据尽快分发恶意软件。对应改进包括：npm 分阶段发布（新包暂存直到额外审批与 2FA 验证）；npm v12 破坏性变更（默认禁用安装脚本；默认禁用 git 或远程 URL 依赖）；Dependabot 版本更新默认包冷却（发布可用至少三天后才开 PR）。
- 识别与响应：自服务凭据撤销（即时撤销企业中给定用户的所有凭据）；扩展凭据撤销 API（支持 GitHub OAuth 与 App token）。
- 让产品默认更安全是 npm 与 GitHub 的优先事项。

## 正文

以下是文章全文翻译。

过去一年出现一种供应链攻击模式，瞄准包仓库与 CI/CD 系统的弱点，把恶意软件快速传播到数百个开源项目。这种恶意软件寻求窃取凭据，既为广泛传播攻击，也为后续利用。我们已多次撰写关于加固供应链的计划：2025 年 9 月的"更安全 npm 供应链计划"、2025 年 12 月的"强化供应链安全：为下一轮恶意软件活动做准备"、2026 年 3 月的"GitHub Actions 2026 安全路线图"。在这篇文章中，我们更新已实施的、直接瓦解一些最常见与最有影响的供应链攻击技术的变更。

**供应链攻击解剖。** 供应链攻击把几个弱点串在一起，没有单一安全能力能阻止它们。应对它们需要整体方法，优先考虑打破攻击链中最有影响环节的缓解措施。攻击在传播方式上各异，但大多数遵循类似技术获得项目初始访问、提升权限并在用户与软件间分发。过去几个月对 npm 与 GitHub Actions 的改进集中于切断特定常见技术，并提供让客户识别与响应这些攻击的方式。

**初始入侵。** 攻击从攻破单个项目开始，通常直接攻破维护者账户或瞄准项目的 Actions 工作流。(1) npm 为高影响账户增加预防性账户保护（2026 年 6 月）：攻击常以针对维护者的钓鱼活动开始。通过此变更，高影响 npm 账户在更改邮箱或使用 2FA 恢复码后进入 72 小时只读模式，给维护者时间在账户被用于发起攻击前响应并恢复。(2) 更安全的 pull_request_target 默认值（2026 年 6 月）：项目 CI/CD 流水线中的常见漏洞是"pwn requests"——工作流在来自分叉的 PR 上触发并执行该分叉提交的不受信任代码。我们改变了 actions/checkout 的默认行为，防止在常见被利用触发器中检出分叉的不受信任代码，除非显式退出。此变更及其对旧版本的回移切断了导致 GitHub Actions CI/CD 工作流代码执行与初始项目攻破的最常见脆弱代码模式之一。(3) 控制谁与什么触发 GitHub Actions 工作流（2026 年 6 月）：新控制允许设置企业、组织或仓库级策略，规定谁被允许触发工作流与允许哪些触发类型，提供可治理、可定制的 Actions 工作流最小权限层。(4) 不受信任触发器的只读 Actions 缓存（2026 年 6 月）：攻击者取得代码执行后，通过投毒跨工作流共享的缓存条目升级到更特权工作流（与凭据）。此变更限制低信任工作流修改与其他工作流共享缓存的能力，直接关闭攻击者把有限影响漏洞变成危及发布与发布工作流所用高特权凭据的常见路径。

**窃取凭据。** 攻击者取得单个包后，聚焦检测并窃取凭据以获得进一步访问并在后续跨生态利用。(1) npm 可信发布现支持 CircleCI（2026 年 4 月）：瓦解这些攻击的头号方法是从 CI/CD 流水线移除长期凭据。可信发布无需长期凭据即可授权发布。加入 CircleCI 让更多人能移除这些攻击试图窃取的凭据。(2) Actions 网络防火墙（技术预览）：记录 Action 工作流运行的所有出站网络流量，以便检测恶意代码下载或向新域名窃取凭据等异常行为。未来工作将启用网络出站限制与策略，在这些攻击导致进一步升级与窃取前阻止它们。

**传播攻击。** 用上一步窃取的凭据尽快分发恶意软件并攻破更多项目与维护者。(1) npm 分阶段发布（2026 年 5 月）：有了分阶段发布，仅凭凭据不足以在 npm 发布新包；包被暂存直到在 npm cli 或 npmjs.com 上提供额外审批与 2FA 认证。通过把 CI/CD 流水线与自动化所用凭据和可发布到注册表的凭据解耦，从 CI/CD 流水线到恶意软件分发的攻击链被切断。(2) npm v12 即将到来的破坏性变更（2026 年 6 月）：攻击者使用 npm 安装时脚本窃取凭据，而非等待包在运行时执行代码。npm v12 默认禁用这些安装脚本；由于脚本在若干流行包依赖的安装过程中有合法用途，可通过批准特定脚本重新启用。默认禁用 git 或远程 URL 依赖也阻止了安装时代码执行的其他向量。(3) Dependabot 版本更新引入默认包冷却（2026 年 7 月）：攻击者依赖速度，希望在任何人注意前让恶意发布进入尽可能多下游项目。经 Dependabot 的版本更新现在等待发布可用至少三天后再打开 PR，给检测信号时间在恶意发布到达项目前浮现。此冷却默认开启，安全更新仍立即打开。

**识别与响应供应链攻击。** 与加固并行，GitHub 也提供工具帮助用户识别与响应影响其项目与账户的供应链事件。(1) 事件响应的自服务凭据撤销（2026 年 6 月）：即时撤销企业中给定用户的所有凭据，建基于 2 月发布的企业级凭据管理工具。(2) 扩展凭据撤销 API 支持（2026 年 3 月）：把凭据撤销 API 的支持扩展到 GitHub OAuth 与 App token，允许快速自服务撤销这些泄露凭据并限制其被滥用的生命周期。

**接下来是什么？** 让产品默认更安全是 npm 与 GitHub 的优先事项，我们正在优先开展针对开源生态供应链攻击的工作。开源软件是令人难以置信的公共品，这是 GitHub 支持开源社区及其依赖企业安全、可持续与持续成功的多种方式之一。
