我们的数据显示，大量来自行为良好机器人的流量都在[重复抓取没有变化过的页面](https://blog.cloudflare.com/making-ai-search-smarter/)。数以十亿计的请求。巨额的机器算力消耗，却完全没有带来任何结果。这正是为人类构建的网络在被另一种访客访问时的典型特征。

智能体已经到来——它不是一种新软件，而是网络的一种新访客。

围绕这种新访客重塑后的网络，就是我们所说的"智能体互联网"（Agentic Internet）。我们预见它的未来是：可读（readable）、可发现（discoverable）、可调用（callable）、可支付（payable）。要实现这个未来，它需要属于自己的工具和协议。

Cloudflare 的开发者平台给了智能体一个运行场所，以及第一批构建智能体的工具。真正缺失的，是让智能体和域名所有者合作而非冲突的那些工具——在开放的互联网上，而不仅仅在单一平台内部。

每个浏览器向来都会通过一个名为 User-Agent 的请求头向网络表明身份。这个名字只有在意识到浏览器是代表你行事时才有意义。如今，用户代理（user agent）真正成为了"用户的代理"：一个代表人类去抓取网络的程序。今天它最成熟的形态是编码智能体——读写代码、拉取所需的文档，却从未"看见"它所读取的页面。

智能体不渲染你的 CSS，不看你的主视觉图，也不点击你的广告。但它的另一端坐着一位付费的人类用户。现在每一个请求都意味着有人花钱，并承载着一个目的。屏蔽它，你就屏蔽了你的客户。把它当爬虫处理，你就会失去他们。

每一个智能体之所以运行，是因为有人——一个人或一家企业——在为它所做的事付费。大多数人不会无缘无故地消耗 token。这个版本的互联网——每个请求的另一端都对应着一个结果和一张账单——将与我们今天所知的互联网截然不同。

网络不是为此而建的，你的分析工具也不是。在大多数情况下，你的商业模式也不是。智能体如何阅读、发现、调用和支付，将决定互联网是保持开放还是走向封闭。在未来的一种版本里，少数几个平台垄断了发现、身份和支付，其他所有人都要经由它们。在另一种版本里，互联网保持开放：建立在人人皆可实现的标准之上的基础组件，运行在因为代码公开而保持中立的轨道上。

Cloudflare 相信开放的互联网，而我们也有能力帮助构建一个让开放互联网繁荣的未来。

我们所依托的规范都是任何人都能实现的开放标准——x402、MCP、Web Bot Auth、PACT。域名所有者可以选择自己的身份提供商、自己的支付处理商、自己的智能体合作伙伴。Cloudflare 只是选项之一，而非整个技术栈。我们是自家客户所用轨道的"零号客户"（Customer Zero），没有任何特权路径或只有我们才能访问的抢先体验 API。这是十五年来我们为人类互联网做的工作，也是我们打算为智能体互联网做的工作。

工程细节并不是人类用户会在智能体互联网上留意的东西。他们接触的是一个新媒介，会用评判网络的方式去评判它：它是不是更好用。预订餐桌是不是从九轮交互变成了一轮。他们是否知道自己正在与谁打交道。支付是否让人安心。

## 我们的理念：一个可读、可发现、可调用、可支付的智能体互联网

一切从身份开始。[Web Bot Auth](https://blog.cloudflare.com/web-bot-auth/) 让机器人能以加密方式向它访问的每个网站证明自己的身份，发布者就能决定欢迎谁、拒绝谁。不再靠猜测，也不再有伪造的 user-agent。许多网站已经通过登录、应用内行为或购买记录知道了请求背后的人类是谁。这样的网站可以签发[私有访问控制令牌](https://cloudflare.net/news/news-details/2026/Cloudflare-Collaborates-With-Leading-Browsers-to-Develop-a-Privacy-First-Protocol-For-the-Global-Internet/default.aspx)（PACT）。PACT 由 Mozilla、Google、Microsoft 和 Shopify 联合发布，让网站可以匿名背书，智能体便能带着令牌去别处出示。合规的智能体可以用更少的摩擦进入。

然后我们可以让智能体更容易完成自己的工作。[Markdown for Agents](https://developers.cloudflare.com/fundamentals/reference/markdown-for-agents/) 让智能体以更少的 token 和带宽阅读网站。[WebMCP](https://blog.cloudflare.com/webmcp/) 为智能体提供了一种代表你与网站交互的原生方式。x402 之类的[标准](https://x402.org/)让它们可以直接向商家付款。

**可读**（Readable）直截了当。AI 智能体能否以对它们而言原生、能发挥它们优势的方式读取内容？智能体消耗的带宽和 token 越少越好。每一个为永远不会看它的人类渲染的 HTML 标签，不仅浪费算力，还污染了智能体的上下文窗口——而智能体还得花钱去忽略这些污染。[Markdown for Agents](https://developers.cloudflare.com/fundamentals/reference/markdown-for-agents/) 从服务器端解决这个问题。

在客户端，我们以把智能体当作一等公民的理念来构建浏览器。[Kitesurf](http://blog.cloudflare.com/kitesurf) 是我们的新浏览器，轻量到可以在 Workers 上运行，按请求创建、用完即弃。它提供智能体所需的内容和功能，却没有传统浏览器里那些面向人类功能的冗余。

**可发现**（Discoverable）是智能体互联网上每一个经济时刻的起点。在智能体读取资源、调用工具或为一次交易付费之前，它必须先知道这个资源的存在。搜索只是故事的一半，因为智能体需要通过为它们构建的界面来找到所需，而不是通过一个为打字慢、喜欢扫读的人类设计的搜索框。[AI Search](https://developers.cloudflare.com/ai-search/) 现已可用，任何公开网站都可以让智能体搜索到。

被发现的另一面同样重要。内容创作者和 API 所有者需要知道自己在智能体面前有多显眼。[Agent Engine Optimization（AEO）](http://blog.cloudflare.com/aeo) 衡量品牌在关键模型和智能体中的可见度。如果你的客户所使用的智能体无法量化地看到你，那么对他们来说，你实际上已经离线了。

**可调用**（Callable）是智能体开始做实事的地方：订一张桌、续一个订阅、拉一份报告。在人类互联网上，这些操作看起来各不相同，因为它们是为人类点击用户界面而构建的。一个想往待办清单里加一项的智能体，得解析 HTML、猜哪个按钮是"添加"、合成一次点击，还要祈祷 DOM 从它上次查看以来没有变过。

[WebMCP](https://blog.cloudflare.com/webmcp/) 让网站可以直接通过浏览器把动作暴露给智能体：

```
document.modelContext.registerTool({
  name: "add-todo",
  description: "Add a new item to the user's active todo list",
  inputSchema: {
    type: "object",
    properties: {
      text: { type: "string", description: "The todo item text" }
    },
    required: ["text"]
  },
  async execute({ text }) {
    await addTodoItemToCollection(text);
    return { content: [{ type: "text", text: `Added: "${text}"` }] };
  }
});
```

工具的"契约"变得明确。不再解析 HTML，不再猜测表单字段。由于工具运行在页面内部，它们复用了用户现有的会话和状态。[Code Mode](https://blog.cloudflare.com/code-mode/) 更进一步。智能体用代码思考，通过写代码来调用工具，比用自然语言更快、更准确。随着智能体改为直接调用端点而非抓取网页，内容所有者也能获得一个清晰的信号：哪些内容真正被使用了。

**可支付**（Payable）是我们认为智能体互联网的归宿。每一笔经济交易最终都需要一种支付方式。广告模式正在崩塌。当用户是一个程序时，按席位（seat）计费的模式也不奏效。我们赖以生存的发布者，无法靠从未发生过的页面浏览和从不渲染广告的浏览器来养活自己。

一个靠广告从未盈利的食谱网站，可以每次抓取收取零点几分钱，就能在智能体互联网的规模下实现盈利。一份地方报纸可以在阅读时按次授权文章，无需授权协议或登录。在另一端，智能体带着一个钱包和人类一次性设定的预算出现。

每一次付费交互都会留下一张收据。发布者可以证明哪个智能体抓取了哪个页面；智能体可以证明它为自己用过的东西付了钱。[Wallets](https://blog.cloudflare.com/wallets/) 让智能体轻松为内容和 API 付费。[Monetization Gateway](https://blog.cloudflare.com/monetization-gateway/) 让域名所有者只需几次点击就能设置从智能体收款。

Cloudflare 有意处于这一切的中心。我们已经站在数十亿人类和他们访问的网站之间，保护他们、为他们加速、让他们保持在线。智能体改变了流量，却没有改变这份工作的形态——我们仍然是那个中立、高性能的层级，发布者、商家、智能体构建者和终端用户都可以信任它站在自己一边，而不是与他们竞争。

我们想给域名所有者提供工具，让他们能够支持自己想支持的 AI 智能体，并[屏蔽他们不想要的](https://blog.cloudflare.com/cloudflare-ai-audit-control-ai-content-crawlers/)。开发者工具可能想变得[智能体就绪](http://blog.cloudflare.com/aeo)（agent-ready），以鼓励 AI 智能体发现、推荐并为他们付费。发布者可能想屏蔽掠夺式的 AI 智能体（只消耗资源而不回馈任何东西），但允许授权其内容或向他们付费的 AI 智能体。非营利数据提供商可能想屏蔽超过速率限制的机器人或人类，但允许他们付费解除限制，并用这些资金覆盖超出的资源消耗。

## 机器人已死，机器人万岁

[机器人和人类之间的区别不再那么简单](https://blog.cloudflare.com/past-bots-and-humans/)。这不再是"机器人坏、人类好"，或者"机器人在浪费本该由人类消耗的资源"那样简单。在智能体的世界里，这种旧思维已经过时了。

我们把智能体看作一种新型参与者。它们的行为可能是可取的——比如以节约资源的方式阅读内容、按域名所有者规定的方式与网站交互、为自己使用的东西付费。也可能是不可取的——比如不付任何补偿地抓取数百万页面、试图绕过封锁、无视 [robots.txt](https://www.cloudflare.com/learning/bots/what-is-robots-txt/)。我们相信，如果给人类和机器人合适的工具，许多不可取的行为会减少，甚至转化为可取的行为。

## 弥合收入缺口

Cloudflare 多年来一直在检测机器人，让域名所有者能够掌控机器人能否访问自己。一直缺失的是另一半：一旦放智能体进来，它们如何与这些网站交互。这正是这套智能体工具集的用途：让网络可读、可发现、可调用、可支付。这四个基础组件全部建立在开放标准之上，因此没有任何一家公司能独占这些轨道。

开放的智能体互联网需要双方都有多样性。不仅要有多元的发布者和内容创作者，还要有多元的智能体。如果需求端走向集中，供应端再开放也无济于事——互联网仍然会是一座围墙花园。
